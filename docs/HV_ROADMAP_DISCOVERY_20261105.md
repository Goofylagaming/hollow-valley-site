# POI discovery — roadmap #10

Local implementation starts with a catalog validator and additive immutable catalog store. Catalog versions identify a map version, explicit bounds, named regions and up to 500 stable POI IDs. Supported categories cover waterfalls, caves, nesting areas, landmarks and territories. Each entry must explicitly enable or disable a circular visit area defined in raw world coordinates and a radius in metres. This does not infer geometry from map labels or paths.

Repeated registration of canonically equivalent rules is idempotent. Changing geometry, names, region assignments or enabled status under an existing version is rejected; a new version preserves the old definition. Different locations may share a display name but cannot share an ID.

Tests use synthetic geometry only. No real location catalog, API, player discovery receipt, map filtering, reward or production rollout is connected yet. Remaining work includes reviewed community-map candidate import, authoritative sample continuity/visit matching, private discovered-only reads, Live Map controls, region completion, territory integration, staging and production validation. No currency payouts or fabricated biome boundaries are introduced.

Visit receipt storage now has a local internal observe entry point behind POI_DISCOVERY_ENABLED. The provisional continuity policy requires two samples in the same catalog and observed life, five to 120 seconds apart, both inside an enabled area, with displacement at most 40m/s. Samples must be at most 30 seconds old. Missing positions break continuity. A single latest sample is stored per player and can be pruned after two minutes; immutable per-player/catalog/point receipts retain the discovery time. Private reads return discovered locations plus the enabled total. Tests cover gap rejection, duplicate timestamps, life changes, account isolation and reopening. The accepted-snapshot connection, consent semantics, scheduled sample cleanup, HTTP boundaries, reviewed real catalog and UI remain pending. Continuity constants are implementation assumptions requiring live validation.

Accepted Legacy snapshots now feed discovery when POI_DISCOVERY_ENABLED=1 and POI_DISCOVERY_CATALOG_VERSION identifies a registered catalog. Players default to collection off. Revision-checked preference changes reset continuity; explicit erasure deletes receipts and disables collection. A consent timestamp rejects observations preceding renewed consent. Savepoints keep visit writes atomic with the enclosing snapshot. A forced receipt-write failure test proves snapshot rollback and successful retry. Account APIs/UI, scheduled cleanup during snapshot outages, real catalog review and live validation remain pending.

Private account APIs are connected at /api/discovery. Website requests bind the Steam actor to the session and use the automation website bearer token internally. The active catalog version comes from automation configuration. Consent and clearing require same-origin JSON, revision checks and writable preview configuration. POI_DISCOVERY_READ_ONLY=1 blocks writes. An isolated two-server HTTP fixture verifies forged actor/catalog parameters, guest access, hidden location privacy, stale revisions, erasure and disabled rollout. Browser controls and reviewed real geometry remain pending.

Temporary discovery samples now expire through startup and the existing 15-second Legacy maintenance timer, independently of snapshot delivery and event-import success. Samples older than two minutes are removed while discovery receipts persist. The maintenance fixture verifies startup and subsequent timer cleanup with a failing combat import. Cleanup requires the Legacy service to run; restart performs catch-up removal. Live Map discovery controls remain pending across its separate point, path and territory layers.

Live Map now has opt-in recording, confirmed progress clearing, refresh and a discovered-only display toggle. In that view the existing point, label, cave/zone shape and Territory overlays are hidden, and a private marker layer shows saved discoveries. Catalog bounds and mapVersion accompany private reads for projection. Desktop/mobile browser fixtures cover filtering, safe names, preference writes, erasure and preview restrictions. Catalog-to-current-map alignment validation, reviewed real points, region completion and staging remain required. The fixture isolates the discovery module; full-map integration still needs staging verification.

Discovery markers now require the active Live Map version and all four coordinate bounds to exactly match the saved discovery catalog. Missing or mismatched map data clears markers and shows a waiting message. Map refresh events recheck alignment. The catalog accepts case-sensitive Gateway version strings with dots, underscores and hyphens while keeping POI identifiers restricted. Desktop/mobile fixtures verify both version and bounds mismatch, followed by restoration. Real catalog geometry and staging verification remain pending.

Region progress now derives from the immutable catalog's enabled POI membership. A region is complete only with at least one enabled point and a receipt for every enabled point in that same version. Completion time is the latest required receipt timestamp. Clearing progress removes completion, and a new catalog version starts independently. The Live Map lists per-region totals without exposing undiscovered POI details. Service fixtures cover partial/full, empty regions, disabled points, version changes and erasure. Cosmetic rewards and reviewed real region membership remain pending.

Candidate review document: scripts/build-discovery-candidates.cjs reproducibly imports 109 disabled entries from the repository map dataset into docs/HV_DISCOVERY_CANDIDATES.json. It records a source SHA-256, attribution and original map metadata. Duplicate identical source rows collapse; different same-named entrances retain separate review IDs. Coordinates convert the source shorthand to world centimetres. Candidate IDs derive from source identity and coordinates, so approved runtime IDs must be assigned/preserved during review if source geometry changes. Region and radius remain null, and non-cave categories require confirmation. This review format cannot be registered as a runtime catalog. Nesting and canonical territory inputs remain outstanding.

Cadence correction: consecutive fresh observations now qualify at any strictly positive time interval up to 120 seconds, preserving speed, same-life and inside-area checks. The former five-second minimum prevented frequent feeds from ever qualifying because each observation replaced the prior sample. A one-second fixture now verifies successful discovery. Runtime inspection found PLAYER_PRESENCE_INTERVAL_MS clamps fallback polling to five to ten minutes; discovery requires a sufficiently frequent external presence feed under its existing two-minute continuity guard. Authenticated staging must verify actual external-feed cadence before enabling collection. Earlier five-second policy text is superseded by this correction.

Tests verify excluded territories stay out and custom battle centers remain supported by existing geometry tests.
