# Group Headquarters — roadmap #16

Local implementation begins with additive group profile metadata. Description edits reuse active group membership and current owner authority from groupsStore. Each edit checks the expected revision and writes the profile plus retained audit entry in one transaction. Members can read their own group's profile and its latest 20 edits. An audit-write failure rolls back the profile update.

Existing groups begin with an empty description and revision zero. This service currently has no website route or UI. Still required are session-bound APIs, same-origin and preview protections, website controls, emblems, expanded member ranks, shared screenshots, verified Territory/battle history integration and staging verification. Group Treasury and diplomacy remain separate incomplete roadmap requirements.

Private /api/group-headquarters routes now expose current-group profile reads and owner updates behind GROUP_HQ_ENABLED=1. Session Steam identity selects the group, with same-origin JSON writes and GROUP_HQ_READ_ONLY/preview restrictions. Responses are private/no-store. HTTP tests cover forged actors, outsiders, members, revisions, cross-origin requests, group isolation, owner succession and disbanding with retained audit entries. Browser controls and remaining Headquarters scope still require implementation.

The Groups page now shows Headquarters description, owner edit controls and recent edit history behind the rollout capability. Members receive a read-only view. Failed saves reconcile authoritative state, and inaccessible groups clear cached profile/history. Group state changes refresh Headquarters while preserving an unsaved same-group description. Isolated 1440px/390px fixtures verify owner/member behavior, safe text, history, preview restrictions and loss of membership. Full-page staging and remaining Headquarters scope are still pending.

Preset emblems are now editable with the description under the same owner permission and revision. Available symbols are leaf, claw, mountain and sun; existing profiles default to leaf. Additive profile/audit columns retain the selected emblem per revision. Description-only callers preserve an existing selection, and arbitrary emblem values fail validation. API and desktop/mobile fixtures pass. Custom image emblems remain a possible extension; expanded ranks, screenshots, battle history and staging are outstanding.

Descriptive member ranks now support member, veteran and officer assignments by the current owner, with revision-checked atomic assignments and retained audit entries. Owner rank follows actual ownership. These labels do not delegate management permissions. Assignment validity includes the member's last exit-history ID, so leaving/removal and rejoining resets the displayed rank even within the same timestamp second. The /ranks account endpoint uses existing session/origin/preview guards. Local service tests cover authority, stale writes, nonmembers, owner protection and rejoin reset. Rank controls and rank audit display remain pending.

The Headquarters panel now displays current member ranks, owner assignment controls and the latest 20 rank audit entries. Members receive display-only ranks; preview mode disables assignment. All member names and audit values use text nodes. Loss of membership clears rank controls and history. Desktop/mobile fixtures verify a versioned rank assignment, member view, safe names and access loss. Shared screenshots, verified battle records and staging remain outstanding.

Group screenshot links now reuse approved gallery images owned by the sharing member. Sharing and removal are transactional with retained action history. Duplicate active shares are idempotent. The sharing member or current group owner can remove a link. Reads join current gallery status and image availability, so rejection or withdrawal hides content immediately. Sharing requires HV_GALLERY_ENABLED, is capped at 50 group links, and uses the existing Headquarters account protections. Local tests cover ownership, pending moderation, duplicates, withdrawal and owner removal. Screenshot picker/display and unavailable-link management remain pending.

The Headquarters panel now offers up to 50 owned approved gallery choices, shared image display and authorized unlink controls. Gallery image URLs use encoded IDs. Unavailable images return only a generic placeholder to the sharing member/group owner, allowing cleanup without exposing moderated titles or pixels. Other members receive approved content only. UI state is cleared on membership loss, and preview controls block writes. Service and desktop/mobile sharing/removal checks pass. Full gallery-to-group staging and Territory identity integration remain pending.

## Territory identity and battle records

Explicit links now connect a website group to a Territory Wars group only when the same Steam account currently owns the website group and leads the Territory group. Names do not establish identity. Link changes require the expected website group ID and revision, preventing a delayed edit from affecting a replacement group. Each change retains an audit entry in the same transaction. A change of leadership suspends new battle attribution. A new dual owner can reclaim a stale association, atomically retaining its revocation history; closed website groups cannot permanently reserve a Territory identity.

New attack declarations freeze the linked website group ID and link revision for each side inside the existing declaration transaction. A savepoint also prevents a partial identity/provenance write when called independently. Retries retain the original identity; later linking never backfills older results. Completed history requires recorded live observation with no disqualification and excludes manual, simulated, testing, nonstandard-start and unobserved results. Records expose only battle/event IDs, side, outcome, timestamps and link revision. No combat roster or live positions are returned. Unlinking or leadership changes preserve previously frozen records.

Members can read up to 50 completed records for their current website group through private/no-store account APIs. The Headquarters panel adds owner linking/unlinking, leadership state and win/loss records. Member views have no edit controls; preview mode disables writes. Response generation checks discard late reads after membership changes, and mismatched group IDs clear the display. Isolated desktop/mobile fixtures pass for these states and safe text rendering. Existing website-group achievements remain available on the Groups page through the established group progression panel.

Local validation covers dual authority, unrelated same-name groups, stale revisions, wrong website group IDs, failed-audit rollback, reclaim rollback, closed groups, immutable declaration attribution, history limits and service reinitialization. HTTP checks cover session binding, forged actor fields, same-origin writes, preview restrictions and member-only history. The runtime fixture exercises actual attack declaration, live capture, unlinking before resolution and exclusion of manually controlled results. These are synthetic fixtures; authenticated staging, real Territory evidence delivery, full-page verification and production rollout remain required. GROUP_HQ_ENABLED defaults off. Roadmap #16 remains Building / Testing, with no production completion date.

## Full Groups page integration

All Headquarters description, rank and screenshot writes now require the website group ID shown when the action began. Delayed requests cannot edit a replacement group even when its revision is also zero. Group-change events invalidate in-flight profile reads, clear prior names, descriptions, ranks, images and audit history, and reload the new group. A read from a departed group cannot repopulate the replacement group's panel.

Unsaved description/emblem drafts survive rank assignments, image sharing/removal, same-group membership refreshes and explicit refresh. A conflicting saved description keeps the original draft revision, preventing silent overwrite on the next save. The user can discard the draft and reload. A save whose response is lost reconciles authoritative state without posting again. Losing owner access clears the editable draft. The Territory form now respects hidden styling, and the Groups footer fits the sidebar layout.

`scripts/verify-groups-page.cjs` runs actual common/navigation code, Groups and Headquarters scripts, private account routes and temporary SQLite storage with synthetic cookie-authenticated identities. It passes at 1440px and 390px for achievements, member ranks, image sharing/removal, draft preservation, conflicting edits, lost save responses, owner/member transitions, leaving and creating a replacement group while an old read is held, delayed wrong-group writes, preview, disabled and guest states. Page-width checks cover owner, screenshot and guest views. It uses a local-only account middleware and suppressed daily claims; it does not verify production Steam authentication or hosted staging. Run with Playwright and a Chromium executable available through the local verification runtime. Authenticated hosted staging and real evidence delivery remain release gates.
